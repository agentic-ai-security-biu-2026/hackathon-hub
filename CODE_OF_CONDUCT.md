# Code of Conduct — Agentic AI Security Hackathon (Kickoff 13 Dec 2026 → deadline 22 Dec 2026)

**Canonical home (when the org is live):**  
`https://github.com/agentic-ai-security-il-2026/hackathon-hub/blob/main/CODE_OF_CONDUCT.md`  
Ship this file as **`CODE_OF_CONDUCT.md` at the root of `hackathon-hub`**. Registration Form 1/2 and the hub README should link there (not only to this planning copy).

**Partners:** Red Hat + Nebius · **Amplifiers:** university Bridge to Industry, campus Cyber Club  
**Scope:** All participants, mentors, judges, and organizers — online and at hybrid opening/closing sessions.

By registering (Form 1) and continuing into Form 2 / the challenge, you agree to this Code of Conduct.

---

## 1. Be respectful

- Treat everyone with respect — students, faculty, mentors, partners, and staff.
- No harassment, discrimination, intimidation, or personal attacks (including on identity, gender, religion, nationality, disability, or background).
- No doxxing, unwanted sexual attention, or sharing others’ private information.
- Disagreements about technical approaches are fine; insults and bad-faith behavior are not.

## 2. In-scope security work only

This is a **security learning event**. Attack and probe **only**:

- Your own team’s project / namespace
- Starter apps and labs provided by organizers
- The Nebius Track 0 CTF environment (if you opted in)

**Out of scope (disqualification + possible ban):**

- Other teams’ projects, namespaces, or credentials
- The shared OpenShift / OpenShift AI demo platform control plane, other tenants, or “break the cluster” goals
- University, Red Hat, Nebius, or third-party production systems
- Random internet targets, phishing, or social engineering of real people outside the provided scenarios

Escape / isolation learning uses **local Podman** or **pre-baked sandbox challenges**, not privilege escalation against the shared demo platform. See the Topics doc “Demo platform safety” section.

## 3. Fair play

- No sabotaging other teams’ work, stealing submissions, or sharing exclusive flags/solutions in a way that breaks Track 0 or challenge scoring.
- Mentors may help conceptually; they will not write your submission for you.
- AI coding assistants (Cursor, Claude, Codex, etc.) are allowed unless a specific challenge says otherwise — you remain responsible for what you submit.

## 4. IP, licensing, and publication

- Submissions must be publishable in the event GitHub org (`agentic-ai-security-il-2026`) for judging (Apache-2.0 preferred unless organizers agree otherwise).
- Do not include secrets, personal data, or material you do not have rights to use.
- Use only synthetic credentials and data from starters / Track 0 — never real API keys, customer data, or production tokens in repos.

## 5. Confidentiality and communications

- Mentors supporting via GitHub issues may see private team repos during the event — that is expected.
- Do not publicly post other teams’ unpublished work without their consent.
- Event photos/recordings at opening/closing may be used for event communications if you consented on Form 2; say so to organizers if you need an exception.

## 6. Safety and wellbeing

- If you feel unsafe or witness a CoC violation, contact organizers immediately (email/Slack channel listed in the hub README when published).
- Organizers may warn, reassign, disqualify, or remove anyone who violates this CoC. Serious cases may be reported to the university Bridge to Industry / Cyber Club contacts as appropriate.

## 7. Reporting

Report concerns to the organizer triage contact listed in `hackathon-hub` (and in registration follow-up mail). You may also escalate to:

- Your university **Bridge to Industry** contact
- Campus **Cyber Club** organizers
- Red Hat / Nebius event leads named in kickoff materials

We will handle reports as confidentially as practical.
